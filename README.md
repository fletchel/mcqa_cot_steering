# mcqa_cot_steering

Steering multiple-choice QA answers along a linear **correctness direction**
in the residual stream, and reading off what the chain-of-thought does when
the answer flips.

We extract the direction from a model's activations on multiple-choice
questions, then intervene along it during chain-of-thought generation. When
the intervention flips the model's final answer, the accompanying reasoning
typically argues for the new answer rather than reflecting the intervention.

```
.
├── final_pipeline/     Orchestrator, per-model/dataset configs, SLURM launchers
├── run_steering.py     Steered CoT generation + answer inspection (called by the pipeline)
└── src/                Core library (data generation, direction extraction, steering, patching)
```

Only code is included; every result and dataset below is regenerated by
running the pipeline (see [Data](#data)).

---

## Pipeline

`final_pipeline/run_full_pipeline.py` runs everything from one YAML config
into an output directory of your choice:

```bash
python final_pipeline/run_full_pipeline.py \
    --config final_pipeline/config_qwen_big.yaml \
    --output_dir runs/qwen_big
# or a subset of stages (later stages read the earlier stages' files from --output_dir):
python final_pipeline/run_full_pipeline.py --config ... --output_dir ... --stages filter direction
```

Stages, in order:

| Stage | Split | What it does |
|---|---|---|
| `filter` | — | Sample MCQs from the configured datasets (MMLU / HellaSwag / TruthfulQA), format with the model's chat template, keep those the model answers correctly (`filtering.min_confidence`), drop negated questions, split into train/dev/test. |
| `direction` | train | Run the model on each formatted question. At the answer-delimiter token of every answer option (and `direction.offsets` positions before it), the correctness direction is `mean(residual at the correct option) − mean(residual at incorrect options)`, one unit vector per (layer, offset). Also stores each class's projection distribution, which sets the steering targets. |
| `patching` | train | Swap-patch residual activations between token-length-matched question pairs to localise where correctness information enters the stream (supporting evidence). |
| `test_projections` | test | Project held-out questions onto the train direction; bias-corrected accuracy/correlation heatmaps. |
| `layer_sweeps` | dev | Per-layer and sliding-window single-token steering sweep (see aside below). |
| `logit_steering` | test | Single-token steering: how often does the correct-vs-target logit difference flip sign. |
| `cot_steering` | test | Full generation under steering: baseline plus steered runs at each `steering.cot_alphas`; final answers are parsed and flip rates reported. |

**Steering** uses *mean matching*: at every steered position the residual's
projection onto the direction is moved to the opposite class's mean, ± α
standard deviations of that class's projection distribution (α =
`steering.cot_alphas`). The correct option's positions are pushed towards the
incorrect-class mean and one randomly chosen incorrect option's positions
towards the correct-class mean. Expressing α in standard deviations makes
steering strength comparable across models and layers.

**Launchers** (SLURM): `final_pipeline/submit_parallel.sh <config> <out>` fans
the stages out as dependent jobs; `run.sh` / `run_2gpu.sh` run one config in
one job. Edit the conda-environment and `HF_HOME` lines at the top of each
for your cluster. `final_pipeline/cot_sample.py` (launcher `run_cot_sample.sh`)
runs a CoT steering sample on a subset of an existing run's test set,
optionally taking the direction from a *different* run — this is how the
cross-direction results below were produced:

```bash
sbatch final_pipeline/run_cot_sample.sh \
    --data_run runs/<run with test data> --direction_run runs/<run providing direction> \
    --num_datapoints 300
```

Configs: one per model/dataset combination (`config_<model>_<dataset>.yaml`;
`default_config.yaml` documents every key). `_smoke` configs are fast
end-to-end checks, `_pilot` small exploratory runs, `_big` / `_5k` the
full-scale runs.

## Indicative results

Qwen2.5-7B-Instruct, CoT steering at α = 2 over **all layers** (authors' runs;
regenerate with the `qwen_mmlu_5k`, `qwen_hellaswag` and `qwen_big` configs
at full scale). *Target rate* = fraction of test questions whose steered CoT
ends in the steering-target (incorrect) answer. Unsteered baselines answer
the target letter 4–5 % of the time.

| Test data ↓ / Direction trained on → | MMLU | HellaSwag | MMLU + HellaSwag |
|---|---|---|---|
| **MMLU** | **50.0 %** (n=1002) | 15.0 % (n=300) | 34.2 % (n=1091) |
| **HellaSwag** | **51.7 %** (n=300) | 25.6 % (n=668) | 41.5 % (n=1077) |

Direction identity dominates: the MMLU direction flips both datasets at ~50 %,
the HellaSwag direction is weak even on its own data, and the mixed direction
lands in between on both. This is not a step-size effect — the α = 2 targets
are the same physical distance for every direction — and the HellaSwag
direction actually separates correct from incorrect projections *better* than
the MMLU one. Probe quality and steering power dissociate.

### Aside: layer selection

The `layer_sweeps` stage picks a best 5-layer window on the dev set by
single-token steering, and `cot_steering` uses it if present. In practice
steering **all layers** flips CoT answers far more reliably than any window
(e.g. HellaSwag at α = 2: 44 % all-layers vs 15 % for the L17–21 window on the
same run), so run with all layers: set `split.dev_fraction: 0.0` (the sweep is
skipped and all layers are used), or list every layer under
`steering.cot_layers`. The `_big` configs do this.

## Data

### Sources and generation

Nothing is bundled; the `filter` stage downloads and builds everything from
HuggingFace datasets (`src/data_generator.py`):

| `datasets:` key | HF dataset / split | Question | Options | Correct |
|---|---|---|---|---|
| `mmlu` | `cais/mmlu`, config `all`, `test` | `question` | `choices` (4) | `answer` |
| `hellaswag` | `Rowan/hellaswag`, `validation` | `ctx` | `endings` (4) | `label` |
| `truthfulqa` | `truthful_qa`, config `multiple_choice`, `validation` | `question` | `mc1_targets.choices` (variable) | label == 1 |

For each item (in a seeded shuffle of the dataset), `generate_and_filter_pairs_hf`
(`src/data_generator_hf.py`):

1. Randomly permutes the options and records `order` (`order[i]` = original
   index of the option shown at position *i*) and `correct_pos`.
2. Builds the **direction-finding prompt** through the model's chat template:
   user turn `"<instruction>\nQuestion: <q>\nChoices: (a) <opt>, (b) <opt>, …\n"`,
   assistant turn prefilled with `"The final answer is ("` (so the next token
   is the answer letter). Instruction is
   `"Answer the following question."` (MMLU, TruthfulQA) or
   `"Complete the following sentence."` (HellaSwag).
3. Locates each option's **delimiter position**: the token index immediately
   after the option text (the comma / newline), found by character-offset
   mapping in `src/utils.py:get_prompt_answer_positions`. Offsets in the
   config are relative to it: `0` is the delimiter, `-1` the option's last
   token, `-2` the one before, etc. With `adaptive_offsets: true` offsets are
   clipped per option so they never reach before the option's first token.
4. Runs one forward pass and keeps the item only if
   `logit(correct letter) − max logit(other letters) ≥ filtering.min_confidence`
   (`0.0` = the model gets it right).
5. Drops questions containing negation words (`not`, `except`, `never`, …).

Kept items are shuffled and split by `split.{train,dev,test}_fraction`.

To produce a dataset without running everything, use the first stage only:

```bash
python final_pipeline/run_full_pipeline.py --config final_pipeline/config_qwen_big.yaml \
    --output_dir runs/qwen_big --stages filter
```

The **CoT prompts** used by `cot_steering` are rebuilt from the same pairs
(`run_steering.py:load_patching_pairs_as_steering_data`): user turn
`"<instruction> Think step-by-step before giving your answer. \n<q>\nChoices: (a) <opt>, (b) <opt>, ….\n"`
with the chat template's generation prompt, no prefill. Delimiter positions
are re-located in this prompt at generation time.

### File formats

All outputs are Python pickles (`pickle.load`) except `direction.pt`
(`torch.load(..., weights_only=False)`). Layout of an output directory:

```
config.yaml                       copy of the config used
data/{train,dev,test,all}.pkl     {'pairs': [pair, …], 'metadata': {...}}
direction/direction.pt            the correctness direction
direction/projections.pkl         train-set projections onto it
direction/projections_bc.pkl      same, position-bias-corrected
patching/patching_{per_offset,all_offsets}.pkl
layer_sweeps/{per_layer,window}/L*.pkl, best_window.pkl
logit_steering/L{layers}_S{alpha}.pkl
cot_steering/intervened_generations_{baseline,L…_S…}.pkl
test_projections/projections.pkl  test-set projections (same format)
plots/*.pdf
```

**`pair`** (one MCQ; the unit everything else is indexed by):

| Key | Type | Meaning |
|---|---|---|
| `question` | str | raw question / context text |
| `subject` | str | MMLU subject or HellaSwag activity label |
| `answer_texts` | list[str] | options in **original** dataset order |
| `correct_idx_original` | int | index into `answer_texts` |
| `order` | list[int] | shown position → original index |
| `correct_pos` | int | shown position of the correct option |
| `gen` | str | the full direction-finding prompt (chat template applied) |
| `delimiter_positions` | list[int] | token index after each option, in shown order (tokenise `gen` with `add_special_tokens=False`) |
| `confidence` | float | correct-letter logit minus best other letter logit |
| `source_dataset` | str | `mmlu` / `hellaswag` / `truthfulqa` |

**`direction.pt`**: `{'directions': FloatTensor (n_offsets, n_layers, d_model)` —
unit vectors, `'offsets': list[int]`, `'layers': list[int]`, `'shape'`, `'metadata'}`.

**`projections.pkl`** (train and test): for each question, the scalar projection
of the residual at every option's steered positions onto the direction.

| Key | Shape / type | Meaning |
|---|---|---|
| `correct_projections` | (N, n_offsets, n_layers) | one row per question, at the correct option |
| `incorrect_projections` | (M, n_offsets, n_layers) | one row per incorrect option, all questions concatenated |
| `incorrect_question_idx` | list[int], len M | question index of each incorrect row |
| `n_choices_per_question` | list[int], len N | |
| `correct_mean`, `incorrect_mean`, `correct_std`, `incorrect_std`, `separation` | (n_offsets, n_layers) | class statistics; steering targets are `incorrect_mean − α·incorrect_std` / `correct_mean + α·correct_std` |
| `letter_logits` | (N, max_n_choices) | final-token letter logits, NaN-padded |
| `correct_positions`, `questions`, `answer_choices` | lists, len N | shown correct position, question text, options in shown order |

Entries are NaN where an offset was clipped by adaptive offsets.
`projections_bc.pkl` additionally holds `position_means` (per shown-position
mean projection) and has them subtracted from every projection.

**`cot_steering/*.pkl`**: `{'results': [...], 'successful_results': [...], 'metadata': {...}}`.
Each result: `question`, `prompt` (the CoT prompt), `response` (generated
text), `answer_texts` (shown order), `correct_idx`, `target_idx` (the
incorrect option steered towards), `delimiter_positions`,
`correct_positions` / `target_positions` (steered token indices per offset),
`intervention_layers`, `intervention_offsets`, `scale`, `success`.
`src/summarize_results.py:extract_answer` parses the final answer letter from
`response`; `run_steering.py --stage inspect` prints the correct / target /
other / unclear breakdown.

**`logit_steering/*.pkl`**: per-question tensors `baseline_ld`, `steered_ld`,
`delta_ld` (logit(correct) − logit(target), NaN if skipped), the individual
letter logits, `correct_pos`, `target_pos`, `questions`, plus `metadata` with
layers / offsets / α. A "flip" is `steered_ld < 0`.

**`patching/*.pkl`**: `metrics` of shape (n_pairs, n_layers, n_offsets)
(per-offset) or (n_pairs, n_layers) (all offsets at once) holding the
normalised logit-difference recovery `(baseline − patched) / (baseline − corrupt)`
(0 = no effect, 1 = full flip), `mean_metrics` averaged over pairs, `layers`,
`offsets`, the `pairs` used, `metadata`.

## `src/`

| Module | Role |
|---|---|
| `data_generator.py`, `_hf.py` | MCQ sampling, chat templating, confidence filtering |
| `direction_finder_hf_streaming.py` | Two-pass streaming direction extraction and projections |
| `direction_finder.py`, `direction_finder_hf.py` | Shared helpers (pair conversion, negation filter, plots, confidence filter) |
| `intervened_generator.py` | Hooked generation with mean-matched residual-stream steering |
| `logit_steering_hf_batched.py` | Batched single-token steering sweeps |
| `activation_patching_hf.py`, `activation_patching.py` | Swap patching and its plots |
| `adaptive_utils.py` | Per-option offset clipping for variable-length options |
| `hf_utils.py` | Model loading, cached forward passes, hooks |
| `utils.py` | Answer-delimiter position finding, direction save/summary |
| `summarize_results.py` | Final-answer extraction and false-positive filtering |

## Environment

```bash
conda create -n mcqa_cot_steering python=3.12
conda activate mcqa_cot_steering
pip install torch transformers datasets accelerate numpy scipy matplotlib pyyaml tqdm
```

The repository is self-contained. Every stage needs a GPU; large models
(70B, GPT-OSS-20B, Qwen3-32B) need 2× A100 — see `run_2gpu.sh`.
